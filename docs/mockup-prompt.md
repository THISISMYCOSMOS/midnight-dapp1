# 목업 생성 프롬프트

아래 구분선 안쪽을 그대로 복사해 Claude 디자인 기능에 붙여넣는다.
결과가 나오면 이 문서 맨 아래 "검토 기준"으로 판정한다.

---

익명 리뷰 웹앱의 화면 목업을 만들어줘. 정적 HTML 한 페이지에 모든 화면과 상태를 세로로 나열해서, 한 번에 비교할 수 있게 해줘. 동작은 필요 없고 화면만 보면 돼.

## 이 앱이 하는 일

상품 후기 게시판인데 세 가지 성질이 있어.

- 누가 썼는지 아무도 모른다. 운영자도 모른다
- 아무나 쓸 수는 없다. 자격자 명단에 있어야 한다
- 한 상품에 한 번만 쓸 수 있다

중요한 건, **자격 여부와 중복 여부를 제출 전에 브라우저에서 이미 알 수 있다는 것**이다. 그래서 실패는 사후 에러가 아니라 사전 상태다. 못 쓰는 사람은 버튼을 누를 수 없고, 왜 못 쓰는지가 그 자리에 적혀 있다.

그리고 제출할 때 암호학적 증명을 만드느라 십수 초가 걸린다. 이게 이 앱에서 유일하게 긴 대기다.

## 디자인 시스템 — 이 값만 쓴다. 새로 만들지 마

**색**

```
배경        #FFFFFF
본문 텍스트  #1A1A1A
보조 텍스트  #6B6B6B
비활성 텍스트 #A0A0A0
구분선      #E5E5E5
```

유채색은 **딱 한 군데**, 증명 생성 진행 표시에만 쓴다: `#2F6F5E`

버튼도 검정(`#1A1A1A`)이다. 실패 상태에 빨강을 쓰지 마 — 이 앱은 실패를 미리 막기 때문에 빨간 에러 화면이 나올 일이 없다.

**타이포 — 3단계만**

```
제목  32px / weight 600 / line-height 1.25
본문  15px / weight 400 / line-height 1.6
보조  13px / weight 400 / line-height 1.5
```

폰트는 시스템 폰트(`-apple-system, "Segoe UI", "Noto Sans KR", sans-serif`). 웹폰트 불러오지 마.

**간격 — 4단계만**

```
4px  8px  16px  32px
```

**컴포넌트**

- 버튼 높이 40px, `border-radius: 4px`
- 입력창 `border-radius: 4px`, 테두리 1px
- **카드 쓰지 마.** 리뷰 항목은 카드가 아니라 위아래 구분선(1px)으로 나눈다
- **그림자 쓰지 마**
- 최대 폭 640px, 가운데 정렬

## 절대 넣지 마

- 이모지, 아이콘 일러스트
- 그라데이션
- 그림자, 둥근 카드
- "🔒 안전하게 보호됩니다" 같은 제품이 자기를 칭찬하는 문구
- "익명", "블록체인", "제로지식" 같은 단어를 배지나 라벨로 붙이는 것
- 진행률 퍼센트 숫자 (실제로 알 수 없는 값이다)
- 화면을 채우기 위한 장식 요소

판단 기준 하나만 적용해줘: **화면의 모든 요소에 "왜 여기 있나"를 물어서, 답이 "예뻐서"나 "허전해서"면 빼.**

## 만들 화면과 상태

### 화면 A — 리뷰 목록

상품명(제목), 그 아래 리뷰 목록. 리뷰 하나는 본문과 작성 시각만 있고 **작성자 정보가 없다**. 지갑 연결 없이 열리는 화면이다. 우측 상단이나 목록 아래에 "리뷰 쓰기" 버튼.

**A-1** 리뷰 4건이 있는 상태
**A-2** 리뷰 0건인 상태 — 문구: `아직 리뷰가 없습니다`

### 화면 B — 리뷰 작성

본문 입력 영역(여러 줄)과 제출 버튼. 자격 상태를 이 화면이 표현한다.

**B-1 지갑 미연결**
입력 영역 비활성. 문구: `리뷰를 쓰려면 지갑을 연결해야 합니다`
버튼: `지갑 연결`

**B-2 자격 없음**
입력 영역 비활성. 문구: `리뷰는 구매 확인된 분만 쓸 수 있습니다`
제출 버튼 비활성

**B-3 이미 작성함**
입력 영역 비활성. 문구: `이 상품에는 이미 리뷰를 남기셨습니다`
제출 버튼 비활성

**B-4 작성 가능**
입력 영역 활성, 본문이 몇 줄 입력된 상태. 제출 버튼 활성

### 화면 C — 제출 진행과 완료

**C-1 증명 생성 중**
입력한 본문은 화면에 남아 있다. 3단계를 보여주는데, 1번은 끝났고 2번이 진행 중이고 3번은 아직이다.

```
자격 확인          완료
증명 생성          진행 중 · 12초
트랜잭션 전송       대기
```

경과 시간(`12초`)은 실제로 흐르는 숫자다. 여기가 유채색 `#2F6F5E`를 쓰는 유일한 자리다. 퍼센트 진행률 막대는 쓰지 마 — 얼마나 남았는지 모르는 게 사실이라, 아는 척하는 UI가 된다.

**C-2 제출 완료**
문구: `제출되었습니다`
바로 아래 방금 쓴 리뷰 본문을 한 번 보여준다.
그 아래 보조 텍스트로: `이 화면을 벗어나면 어느 리뷰가 내 것인지 확인할 수 없습니다`
버튼: `목록으로`

이 마지막 안내 문장이 이 앱의 성격을 가장 짧게 설명하는 자리다. 사과하거나 변명하는 톤이 아니라, 사실을 담담하게 말하는 톤으로 보이게 해줘.

## 문체

모든 문구는 한국어 존댓말이고 담백하다. 느낌표 쓰지 마. 사용자를 격려하거나 안심시키려 들지 마.

각 화면 위에 `A-1 리뷰 목록` 같은 라벨을 작게 달아서 구분해줘. 이 라벨은 목업 확인용이라 실제 화면 요소가 아니니까 회색 보조 텍스트로 작게.

---

## 검토 기준

결과가 나오면 이걸로 판정한다. 하나라도 걸리면 다시 요청한다.

**반드시 확인**

- [ ] 그림자·그라데이션·이모지가 없는가
- [ ] 리뷰 항목이 카드가 아니라 구분선으로 나뉘어 있는가
- [ ] 유채색이 C-1 진행 표시 외의 곳에 쓰이지 않았는가
- [ ] 실패 상태에 빨강이 안 들어갔는가
- [ ] 타이포가 3단계, 간격이 4단계를 넘지 않는가
- [ ] 제품이 자기를 설명하는 문장이 없는가
- [ ] 리뷰 항목에 작성자를 암시하는 요소(아바타, 닉네임, 등급)가 없는가
- [ ] C-1에 퍼센트 진행률이 없는가

**요소별로 물을 것**

화면에 있는 모든 요소에 "왜 여기 있나"를 묻는다. 답이 "예뻐서" 또는 "허전해서"면 뺀다.

**남는 판단**

색·간격 값은 목업을 보고 조정한다. 지금 값은 시작점이지 확정이 아니다.
