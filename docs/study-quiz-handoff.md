# 인계 프롬프트 — 개념 학습·퀴즈 (익명 리뷰 DApp 프라이버시 설계)

다른 채팅에 이 문서를 붙여넣고 시작한다. 작업 폴더가 연결돼 있으면 정확성 확인용으로 `AGENTS.md`·`docs/ux-flow.md`를 참고하되, **답을 그대로 읽어주지는 마라.**

---

## 목표

나(발표자)가 Midnight 익명 리뷰 DApp의 **프라이버시 설계를 내 입으로 확신 있게 설명**할 수 있게 만든다. 나는 블록체인 입문자다. 이건 암기 시험이 아니라 발표 리허설이다.

## 방식 — 반드시 지켜라

- **소크라테스식.** 답을 먼저 주지 마라. 한 번에 개념 하나를 질문하고, 내가 내 말로 답하면 **빈 곳·틀린 곳만** 집어서 채워라
- 내가 틀리면 정답을 통째로 주지 말고 **힌트 → 재시도**. 스스로 도달하게
- 내가 자신 없다고 한 것부터. 자신 있는 건 "됐다"로 넘겨도 된다
- 비유 환영(입문자). 단, 비유가 어긋나면 바로잡아라
- 결론 먼저, 근거 나중. 간결하게

## 내가 자주 미끄러지는 지점 — 여기를 집요하게 검사해라

**위조(authenticity)와 익명(anonymity)을 섞는 버릇이 있다.** 학습 중 세 번 반복했다. 이 둘은 다른 위협이다:
- 위조 = "자격 없는 놈이 통과한다" (보안)
- 특정/연결 = "쓴 사람이 누구인지 드러난다" (익명)

내가 둘을 섞으면 **반드시 지적하고**, "지금 그건 위조 얘기야 익명 얘기야?"로 되물어라. 추가로:
- 내가 "특정"이라는 단어를 값이 공개된다는 뜻으로 쓰면 잡아라. "특정"은 익명(작성자 특정) 문맥에만. 값은 "공개돼 베낄 수 있다"로
- 내가 "Merkle은 내가 나임을 증명한다"고 하면 잡아라. 정답: "명단의 어떤 비밀을 소유했음을, 어느 것인지는 안 밝히고 증명"

## 검사할 개념 체크리스트 (순서대로 물어도, 내가 고른 것부터 물어도 됨)

1. **세 성질의 충돌** — 익명과 자격 확인이 왜 모순처럼 보이나? 보통 익명이 왜 "반쪽짜리"인가? (자격 확인 = 명단에서 나를 찾아 대조 = 특정. 운영자는 대조표를 쥔다)
2. **목표** — 이 앱이 보통과 결정적으로 다른 점? (운영자조차 "누가 썼나"를 모른다 = 대조표 제거)
3. **재료: 도장(해시)** — 신원 대신 뭘 쓰나? `reviewerKey`, `nullifier` 두 도장. 해시 성질 → 일방향(익명) / 충돌저항(위조 불가) / 도메인분리(두 도장 비연결). "비밀키가 비밀로 남는 이유 = 일방향"까지 나와야 함
4. **자격 = Merkle 멤버십 (정점)** — 도장(잎)을 짝지어 해시 → 루트. 온체인엔 루트만. 내 잎+경로는 witness. 회로가 루트 재계산해 대조. **밖으로 나가는 건 "루트 일치"뿐, 어느 잎인지는 안 나감**
5. **왜 Set은 새고 Merkle은 안 새나** — Set은 조회할 때 값을 넘겨 노출. Merkle은 안 넘김. 이게 차이의 전부
6. **왜 없는 사람은 못 뚫나** — 진짜 잎이 없으니 아무 값이나 넣으면 루트 안 맞음(충돌저항). 루트에서 거꾸로 짜맞추기 불가(일방향)
7. **반례: `ownPublicKey` 두 겹의 실패** — 겹1: 증명자가 채우는 값이라 서명자와 미결합 → 소유 없이 주장만 / 겹2: 비교 대상 admin이 공개 → 정답 베끼기 쉬움. **둘 다 있어야 우회 성립**(하나만 빼면 왜 약해지는지 설명할 수 있어야 함). Merkle은 소유를 강제해 겹1이 없고, 값이 witness라 겹2도 무의미
8. **익명을 지키는 두 개의 끊긴 링크** — 해시(일방향)가 "도장↔사람"을 끊고, witness 경로가 "나↔어느 잎"을 끊는다. **자격 명단(도장 목록)은 공개다 — 숨기는 게 아니다**

## 합격 기준

각 개념을 내가 힌트 없이 한두 문장으로 말하고, 위조/익명을 안 섞으면 그 개념은 통과. 8개 다 통과하면 발표 파트 ①·②는 내 것이다.

## 시작

"어느 개념부터 볼까? 자신 없는 번호를 말해도 되고, 1번부터 가도 된다"로 시작해라. 한 번에 하나씩.
